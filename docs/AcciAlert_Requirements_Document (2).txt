1. Project Explanation
AcciAlert is a miniature smart-car prototype that shows how technology can stop accidents before they happen and
call for help immediately if one does. A laptop running Python and OpenCV first checks that the person in the driver's
seat is an authorised driver (face recognition). An ESP32 microcontroller then reads five types of sensors and
decides, in real time, whether the car is safe to run. Everything is displayed on a live Flask web dashboard and stored
as an event log.
What the system does
• Driver authorisation - webcam + face recognition; unknown face = vehicle stays locked.
• Alcohol detection - MQ-3 sensor; if alcohol is above the threshold the vehicle will not start / is stopped and a
buzzer sounds.
• Speed monitoring - IR speed sensor measures wheel speed; over-speed triggers a warning and automatic speed
reduction.
• Obstacle detection - HC-SR04 ultrasonic sensor; car slows and brakes automatically when something is close.
• Accident detection - MPU6050 detects a sudden impact or roll-over; the car stops and the system raises an
emergency.
• GPS tracking + emergency SMS - NEO-6M gets the position; SIM800L sends an SMS 'Accident Alert! Lat/Lon' to
the emergency contact.
• Traffic signal control - Red / Yellow / Green LEDs on the miniature road; the car obeys the signal state.
• Live dashboard + event logging - speed, alcohol level, distance, location, driver identity and all events in real
time.
NEW CONCEPT ADDED: Danger Zone Detection and Dashboard Alert
• Accident-prone places (sharp curves, school zones, junctions, black spots, construction areas) are stored as
geofenced danger zones (latitude, longitude, radius, speed limit, severity).
• When the car's GPS position enters a zone, the system raises a live alert on the dashboard (red banner, map
highlight, sound), the buzzer warns the driver, the speed limit of the zone is applied, and the event is logged.
• When the car leaves the zone the alert clears automatically. See Section 8 for full details.
How the flow works (end to end)
1) Laptop recognises driver > sends AUTH_OK to ESP32 2) ESP32 enables motors 3) Sensors stream data to
ESP32 every 200 ms 4) ESP32 applies safety rules and drives motors/buzzer/signals 5) ESP32 sends telemetry
(JSON) to the laptop over USB serial 6) Flask dashboard shows live data, checks danger zones, stores events 7) On
accident the ESP32 reads GPS and sends an SMS through the SIM800L.

5.2 Power design
• Battery: 2S 18650 pack (7.4 V) with protection board. Add a main switch and a fuse (2-3 A).
• Rail A - motors: battery direct to L298N 12V input (its onboard 5V regulator is not used for the ESP32).
• Rail B - 5 V logic: LM2596 buck set to 5.0 V (3 A) for ESP32 VIN, MQ-3 heater, HC-SR04, MPU6050 (3.3 V from
ESP32 pin), IR sensor, buzzer.
• Rail C - 4.0 V GSM: a second buck set to 4.0 V (min 2 A) only for the SIM800L, with 1000 uF + 100 uF capacitors
at the module. The ESP32 3.3 V pin can NOT power the SIM800L.
• Common ground: all grounds joined at one point. Keep motor wires away from GPS/GSM antennas to reduce
noise.
• While connected to the laptop by USB, the ESP32 may be powered from USB for bench testing; for the road test
use Rail B.

8. NEW Concept: Danger Zone Detection and Dashboard Alert
Goal: warn the driver and the monitoring operator when the vehicle moves into an area known to be dangerous,
before an accident occurs. This adds a preventive layer to the existing reactive accident detection.
8.1 What is a danger zone
Zone type Example Default speed limit Severity
Accident black spot Junction with repeated accidents 10 km/h (scaled) High
Sharp curve Blind turn on the miniature road 8 km/h Medium
School / hospital zone Pedestrian crossing area 5 km/h High
Construction / road work Barricaded section 5 km/h Medium
Restricted / no-entry Closed road 0 (stop) Critical
8.2 Zone data model (SQLite table danger_zones / zones.json)
Field Type Example
id text Z03
name text School crossing
type text school
lat, lon float 13.0830, 80.2710
radius_m float 30 (real) - for the miniature demo see 8.5
speed_limit int 10
severity enum low / medium / high / critical
active bool 1
8.3 Detection algorithm
• Every GPS update (1 Hz) the laptop (and ESP32 as backup) computes the haversine distance from the vehicle
to each active zone centre.
• If distance <= radius and the vehicle was previously outside > ENTER event. If distance > radius + 5 m hysteresis
and it was inside > EXIT event (hysteresis prevents flicker).
• Optional pre-warning ring: distance <= radius + 20 m shows a yellow 'Approaching danger zone' notice.
• On ENTER: log event, push 'alert' via WebSocket, send LIMIT command to ESP32, ESP32 beeps twice and caps
speed.
• If the vehicle exceeds the zone limit while inside, escalate to OVERSPEED_IN_ZONE (high) and log it.
• Critical zones (no-entry): ESP32 stops the car and the dashboard shows a red full-width alert until operator
presses Acknowledge.
8.4 Dashboard behaviour for danger zones
• Map layer: all zones drawn as coloured circles (red high, orange medium, yellow low); vehicle marker moves live.
• Alert banner: 'DANGER ZONE: School crossing - limit 10 km/h' with severity colour, timestamp and alert sound;
stays until the vehicle exits or the operator acknowledges.
• Zone counter card: zones entered today, current zone, time spent inside.
• Event table: ZONE_ENTER / ZONE_EXIT / OVERSPEED_IN_ZONE rows with driver, speed and coordinates.
• Zone manager page: click on the map to add a zone, set radius/limit/severity, enable or disable, delete.
8.5 Indoor miniature demo (important practical note)
GPS does not work reliably indoors and a 1 m track is smaller than GPS accuracy (2.5-5 m). So the team will support
two modes, selectable on the dashboard:
• Real GPS mode - for outdoor tests with a real NEO-6M fix.

• Simulation / track mode - the miniature track is mapped to virtual coordinates (e.g. 1 cm = 1 m around a base
lat/lon). The ESP32 estimates position by dead-reckoning (speed from the IR sensor + heading from the MPU6050
gyro) or from checkpoint markers (IR/line markers or taps) placed at zone entrances. The same zone engine then
runs on these virtual coordinates.
Both modes use the same JSON fields (lat, lon, fix), so the dashboard and zone engine do not change. Owners: zone
engine and DB - Prasanth; dashboard layer and zone manager - Muniyappan; ESP32 backup check and
dead-reckoning - Selvamani; GPS data quality - Sidharraj; track markers and physical zone signage - Nivash.
8.6 Acceptance criteria
• Dashboard shows the alert within 1 second of the vehicle entering a zone and clears it within 2 seconds of exit.
• ENTER and EXIT events logged exactly once per crossing (no flicker).
• Zone speed limit applied by the ESP32 in 3 out of 3 trials; buzzer double beep heard.
• At least 5 zones configured, edited and removed from the dashboard without restarting the server.
• Works with the laptop disconnected (ESP32 backup applies limit; alert is logged and synced when reconnected -
nice to have).

12. Implementation Strategy and Timeline
12.1 Approach
• Interfaces first: freeze pin map and JSON protocol in Week 1 so hardware and software work in parallel.
• Module by module: every member bench-tests their part alone, then it is integrated one module at a time (never
all at once).
• Mock first: software team uses mock telemetry until real hardware is ready; hardware team uses test sketches
until firmware is ready.
• Safety logic lives on the ESP32, not the laptop, so the car stays safe if the laptop link drops.
• Weekly cycle: Monday planning (30 min), mid-week 15-min stand-up, Friday integration test + demo to the team.
• Communication: one group chat, one GitHub repo, one shared drive for photos, datasheets and this document.

15. Appendix
A. Haversine danger-zone check (Python, server/zones.py)
import math
def dist_m(lat1, lon1, lat2, lon2):
R = 6371000
p1, p2 = math.radians(lat1), math.radians(lat2)
dp, dl = p2 - p1, math.radians(lon2 - lon1)
a = math.sin(dp/2)**2 + math.cos(p1)*math.cos(p2)*math.sin(dl/2)**2
return 2*R*math.asin(math.sqrt(a))
def update(zone, inside_before, lat, lon):
d = dist_m(lat, lon, zone['lat'], zone['lon'])
if not inside_before and d <= zone['radius']: return 'ENTER'
if inside_before and d > zone['radius'] + 5: return 'EXIT'
return None
