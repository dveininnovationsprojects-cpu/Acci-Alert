Importance is our assessment from the requirements document (Must items,
dependencies and the project definition of done), not a ranking the document states.
Shared stack for all four: Python 3.10+ on the laptop, Git with a private GitHub repo
(branches: main, hardware, firmware, ai, dashboard), JSON-line messages over USB serial
at 115200 baud, and a weekly Friday integration test.
Selvamani: ESP32 firmware and safety logic
Importance: Critical. Every safety decision (accident, alcohol, obstacle, speed, danger
zone, signal) runs in this firmware, and it must keep the car safe even if the laptop link
drops. He also freezes the pin map and JSON protocol in Week 1, which unblocks the other
seven members.
Tech stack
Tasks
Create the GitHub repo, branch rules and folder structure; run the weekly integration.
Write the firmware skeleton: pins.h , state machine (LOCKED, READY, RUNNING,
WARNING, EMERGENCY), non-blocking loop using millis() .
Integrate sensor code from Yasik, Nivash and Sidharraj, and implement the 7 priority
rules (accident first, signal red last).
Implement the JSON telemetry (every 200 ms) and the command parser (AUTH,
SIGNAL, LIMIT, ZONES, STOP, RESET).
Implement the backup danger-zone check and dead-reckoning for simulation mode.
Implement motor control (smooth stop, speed limiting) with Navin.

Language / IDE C++ (Arduino) on Arduino IDE 2.x or PlatformIO,
ESP32 board package
Libraries TinyGPSPlus, Adafruit MPU6050 (or
MPU6050_light), ArduinoJson
Hardware interfaces ADC (MQ-3), I2C (MPU6050), UART (GPS, GSM,
laptop), PWM (L298N), interrupt (IR speed)
Project tooling Git and GitHub: repo, branch rules, weekly release

Arsal: face recognition and driver authorisation
Importance: High. The car starts only afterArsal's module sends AUTH_OK, so a failure
here either locks out real drivers or lets strangers in. It is the first step of the demo
scenario.
Tech stack
Tasks
Collect face images of 3 to 5 authorised drivers, 20+ images each, in different lighting.
Build recognition (encodings or LBPH), set the confidence threshold, handle no-face
and multiple-face frames.
Send AUTH commands to the ESP32, for example
{"cmd":"AUTH","ok":1,"driver":"Arun"} .
Add liveness basics (blink or movement) if time permits.
Log recognition events to the database through the API.

OpenCV LBPH, numpy

Definition of done: the zone engine passes all unit tests, there are zero duplicate ENTER
or EXIT events (test T11: exactly 10 of each over 10 crossings per zone), and the test report
is signed off each week.
Zone acceptance criteria to design for: alert on the dashboard within 1 s of entry and
cleared within 2 s of exit; at least 5 zones added, edited and removed without restarting
the server; ESP32 applies the zone limit in 3 of 3 trials.
