# AcciAlert ESP32 Device API (version 2)

The ESP32 talks to the Python backend over Wi-Fi with plain HTTP and JSON:

1. **Pair once** with `POST /api/v1/device/register`. The backend gives the ESP32 its device id and a secret token.
2. **Send readings** with `POST /api/v1/telemetry` (sensors and alert flags, stored in the database and shown live on the dashboard).
3. **Collect commands** with `GET /api/v1/device/commands` (the dashboard's STOP, RESET, ACK, AUTH and LIMIT, and the lock state).
4. **Confirm commands** with `POST /api/v1/device/commands/ack`, so the same command is never run twice.

**No API key and no device id are written in the Arduino source code.** The device id is configured on the backend. The token is created by pairing and kept in the ESP32's flash memory (Preferences). The only constant in the firmware is the server address.

## 1. Routes

Base URL: `http://<laptop-ip>:5173` (this laptop: `http://192.168.1.19:5173`, check with `ipconfig`, see section 9).

| Route | Token | Purpose |
|---|---|---|
| `POST /api/v1/device/register` | No (pairing window must be open) | Trade the MAC address for a device id and a token. Once only |
| `POST /api/v1/telemetry` | Yes | Send one reading |
| `GET /api/v1/device/commands` | Yes | Commands waiting for this ESP32, plus the lock state |
| `POST /api/v1/device/commands/ack` | Yes | Confirm commands |
| `GET /api/v1/telemetry?limit=50` | Yes | Newest stored readings (1-500) |
| `GET /api/v1/ping` | No | Connectivity check |

All requests with a body use `Content-Type: application/json`. All responses are JSON.
The token is sent as `Authorization: Bearer <token>`.

## 2. Device ID and pairing (backend side)

The device id comes from the backend: `DEVICE_ID` in `backend/config.py` (default `ACCIALERT_ESP32_01`, override with the environment variable `ACCIALERT_DEVICE_ID`). It is created on the first start with the status `pending`. More cars: `python -m backend.tools.devices add --id ACCIALERT_ESP32_02`.

To connect an ESP32, the operator opens a **pairing window** on the laptop:

```
python -m backend.tools.devices pair --id ACCIALERT_ESP32_01 --mac AA:BB:CC:DD:EE:FF
```

* `--mac` is the ESP32's MAC address (the firmware prints it on the serial monitor at boot). With it, no other device on the Wi-Fi can claim the slot. Without it, the first device that asks within the window gets it.
* The window stays open for 15 minutes (`--minutes` changes this) and closes as soon as the device has paired.
* Other commands: `list`, `reset` (forget the token, pair again), `disable`, `enable`, `remove`, `commands` (recent queued commands).
* If a token is lost or the ESP32 is replaced: `reset`, then `pair` again.

How the token is protected:

* It is 43 random characters, generated by the backend, and **shown only once** in the register response.
* The backend stores only a SHA-256 hash of it. Nobody can read it back from the database.
* A device id in a request body cannot be used to pretend to be another device: the id belongs to the token.
* After 10 wrong registration attempts from one address, that address gets `429` for 5 minutes.
* The server is plain HTTP. Use it only on your own trusted Wi-Fi.

## 3. POST /api/v1/device/register

Sent by the firmware when it has no stored token.

Request:

```json
{ "mac": "AA:BB:CC:DD:EE:FF", "firmware": "1.0.0" }
```

| Field | Type | Notes |
|---|---|---|
| `mac` | string, required | `WiFi.macAddress()`. Six hex pairs, `:` or `-` between them |
| `firmware` | string, optional | Up to 32 characters, shown in `devices list` |

Response `201 Created`:

```json
{
  "status": "success",
  "device_id": "ACCIALERT_ESP32_01",
  "token": "kJ3...43 characters...",
  "token_type": "Bearer",
  "message": "Store the token in flash (Preferences). It is shown only once."
}
```

| HTTP | `code` | Meaning and what the firmware does |
|---|---|---|
| 400 | `invalid_json` | Body is not a JSON object |
| 403 | `pairing_closed` | No pairing window is open for this device. Wait 10 s and try again, and tell the operator to run `pair` |
| 409 | `already_registered` | This MAC already has a token. Tell the operator to run `reset` |
| 413 | `payload_too_large` | Body over 1024 bytes |
| 422 | `invalid_mac` | `mac` is missing or malformed |
| 429 | `too_many_attempts` | Too many failures. Wait 5 minutes |

## 4. POST /api/v1/telemetry

Header: `Authorization: Bearer <token>`. Body at most 4096 bytes. Suggested rate: one reading per second.

`device_id` is **optional** with a token. If it is sent it must match the token (otherwise `403 device_mismatch`).

```json
{
  "timestamp": "2026-11-14T11:00:00+05:30",
  "sensors": {
    "alcohol_adc": 1250,
    "distance_cm": 45.6,
    "accelerometer": { "x": 0.12, "y": 0.08, "z": 9.72 },
    "gyroscope":     { "x": 0.02, "y": 0.01, "z": 0.03 },
    "speed_rpm": 85,
    "ir_pulse_count": 20,
    "gps": { "latitude": 12.841901, "longitude": 80.224845, "fix_valid": false, "satellites": 0 }
  },
  "alerts": {
    "alcohol": false, "overspeed": false, "accident": false, "obstacle": false, "buzzer": false
  }
}
```

### Field rules

All fields below are required. Unknown extra fields are ignored.

| Field | Type | Allowed values | Notes |
|---|---|---|---|
| `device_id` | string | 1-64 characters: letters, digits, `_` `.` `-` | Optional with a token |
| `timestamp` | string | ISO 8601, for example `2026-11-14T11:00:00+05:30` or `...Z` | Use NTP on the ESP32 |
| `sensors.alcohol_adc` | integer | 0 to 4095 | MQ-3 raw ESP32 ADC reading (12-bit) |
| `sensors.distance_cm` | number | 0 to 500 | HC-SR04 |
| `sensors.accelerometer.x/y/z` | number | -160 to 160 | **m/s²** (about 9.8 on the axis pointing up when still) |
| `sensors.gyroscope.x/y/z` | number | -2000 to 2000 | **degrees per second** |
| `sensors.speed_rpm` | number | 0 to 20000 | Wheel RPM |
| `sensors.ir_pulse_count` | integer | 0 or more | Pulses from the IR sensor |
| `sensors.peak_accel_g` | number, **optional** | 0 to 160 | Strongest acceleration (g) of the last second, sampled 10 times a second. With `peak_gyro_dps` it lets the server tell a roll-over (hard knock or fast spin) from a hand slowly turning the car |
| `sensors.peak_gyro_dps` | number, **optional** | 0 to 5000 | Strongest spin (degrees per second) of the last second |
| `sensors.gps.latitude` | number | -90 to 90 | |
| `sensors.gps.longitude` | number | -180 to 180 | |
| `sensors.gps.fix_valid` | boolean | `true` / `false` | A JSON boolean, not 0/1 or "true" |
| `sensors.gps.satellites` | integer | 0 to 64 | |
| `alerts.alcohol`, `alerts.overspeed`, `alerts.accident`, `alerts.obstacle`, `alerts.buzzer` | boolean | `true` / `false` | The ESP32's own decisions and buzzer state |

### Responses

`201 Created`:

```json
{
  "status": "success",
  "id": 1,
  "device_id": "ACCIALERT_ESP32_01",
  "received_at": "2026-11-14 11:28:00",
  "stored": true,
  "dashboard_updated": true,
  "server_alerts": [],
  "warnings": ["gps.fix_valid is false: coordinates are stored but not used for danger-zone checks"],
  "commands_pending": 0
}
```

`commands_pending` is how many commands are waiting. When it is above 0 the firmware may call GET `/device/commands` straight away instead of waiting for its next poll.

| HTTP | `code` | When |
|---|---|---|
| 400 | `invalid_json` | Body is empty or not valid JSON |
| 401 | `unauthorized` | Missing, wrong or reset token. The firmware should delete its stored token and register again |
| 403 | `device_mismatch` | `device_id` in the body is not the token's device |
| 413 | `payload_too_large` | Body over 4096 bytes |
| 415 | `unsupported_media_type` | Content-Type is not `application/json` |
| 422 | `validation_failed` | A field is missing, has the wrong type or is out of range. Lists **every** problem in `errors` |
| 500 | `storage_error` | Reading was valid but could not be saved. Retry with the next reading |

Example 422:

```json
{
  "status": "error",
  "code": "validation_failed",
  "message": "One or more fields are invalid.",
  "errors": [
    { "field": "sensors.alcohol_adc", "error": "must be between 0 and 4095 (got 99999)" },
    { "field": "sensors.gps.latitude", "error": "must be between -90 and 90 (got 123)" }
  ]
}
```

## 5. GET /api/v1/device/commands

Header: `Authorization: Bearer <token>`. Query: `limit` (1-50, default 10). Poll about once per second.

Response `200 OK`:

```json
{
  "status": "success",
  "device_id": "ACCIALERT_ESP32_01",
  "server_time": "2026-11-14T11:28:05+05:30",
  "state": { "auth": 1 },
  "count": 2,
  "commands": [
    { "id": 17, "type": "AUTH",  "value": 1,    "created_at": "2026-11-14 11:28:04", "expires_at": "2026-11-14 11:29:04", "attempt": 1 },
    { "id": 18, "type": "LIMIT", "value": 40,   "created_at": "2026-11-14 11:28:04", "expires_at": "2026-11-14 11:29:04", "attempt": 1 }
  ]
}
```

### The command object

| Field | Type | Meaning |
|---|---|---|
| `id` | integer | Unique command id. Use it to confirm the command and to skip repeats |
| `type` | string | One of the types below |
| `value` | number or null | Depends on the type |
| `created_at`, `expires_at` | string | Server local time. A command is dropped if not collected before `expires_at` (60 s) |
| `attempt` | integer | 1 the first time, higher if it is offered again because it was not confirmed |

### Command types

| `type` | `value` | What the ESP32 does |
|---|---|---|
| `AUTH` | `1` or `0` | `1`: the driver passed the face check, the car may start. `0`: lock the car |
| `STOP` | `null` | Emergency stop: motor off, buzzer on |
| `RESET` | `null` | Clear the stop and the alerts, return to normal |
| `ACK` | `null` | The operator acknowledged the alert: silence the buzzer |
| `ZONES` | object `{version, count, zones[]}` | The current danger zones (see below). Keep them in RAM or flash and replace the old list |
| `LIMIT` | number, **km/h** | New speed limit (set by a danger zone or by the operator). **`0` means "no zone limit": go back to the car's own default limit.** Convert km/h to wheel RPM with `rpm = kmh × 1000 / (60 × 0.204)` (0.204 m is the wheel circumference, `WHEEL_CIRCUMFERENCE_M` in `config.py`) |

### The ZONES command

Sent when the ESP32 registers, when the server starts, and every time a zone is added, edited or deleted (only active zones, at most 100). Example `value`:

```json
{ "version": "3fa91c02", "count": 2, "zones": [
  { "id": "Z01", "name": "Marina school zone", "lat": 13.0500, "lon": 80.2824, "r": 150.0, "limit": 25, "sev": "high" },
  { "id": "Z02", "name": "Hospital", "lat": 13.0604, "lon": 80.2496, "r": 120.0, "limit": 30, "sev": "medium" } ] }
```

`r` is the radius in metres, `limit` the zone speed limit in km/h, `version` an 8 character code that changes whenever a zone changes (ignore a list whose version you already hold). Acknowledge it like any command. The server still decides entry, exit and warnings and sends `LIMIT`; the list lets the ESP32 show or use the zones itself. The full list can be about 4 KB, so give the ArduinoJson document at least 8 KB.

### The lock state

`state.auth` is the lock state **right now**: `1` unlocked, `0` locked. It comes with every response. The firmware must **start locked** and unlock only when it has read `state.auth = 1` (from this response or from an `AUTH 1` command). That way a reboot or a lost command can never leave the car unlocked by mistake. Recommended: lock the car again if the server has not answered for several seconds.

### Order and repeats

* Commands are sorted oldest first. Run them in that order.
* A newer `AUTH` replaces an older `AUTH` that is still waiting, and the same for `LIMIT` and `ZONES`. The firmware will only ever see the latest value.
* `STOP`, `RESET` and `ACK` are never merged.

### Errors

| HTTP | `code` | When |
|---|---|---|
| 400 | `bad_request` | `limit` is not a number |
| 401 | `unauthorized` | Missing, wrong, reset or disabled token. (The old shared API key does not work here) |

## 6. POST /api/v1/device/commands/ack

Header: `Authorization: Bearer <token>`. Tell the backend what happened to each command.

```json
{
  "acks": [
    { "id": 17, "result": "executed" },
    { "id": 18, "result": "rejected", "detail": "limit below minimum" }
  ]
}
```

A single answer may also be sent without the list: `{ "id": 17, "result": "executed" }`.

| Field | Type | Notes |
|---|---|---|
| `acks` | list of 1-50 | |
| `acks[].id` | integer | `id` from the commands list |
| `acks[].result` | string | `executed`, `rejected` (the ESP32 chose not to run it) or `failed` |
| `acks[].detail` | string, optional | Short reason, shown in `devices commands` |

Response `200 OK`:

```json
{ "status": "success", "acknowledged": [17, 18], "already_done": [], "unknown": [] }
```

* `acknowledged`: recorded now.
* `already_done`: it had been confirmed before. Sending the same acknowledgement twice is harmless.
* `unknown`: no such command for this device.

Errors: `401 unauthorized`, `415 unsupported_media_type`, `400 invalid_json`, `422 validation_failed` (lists every problem).

### How a command stays "run once"

1. The dashboard queues a command. The backend gives it an `id` and the status `pending`.
2. The ESP32's GET returns it and the backend marks it `delivered`.
3. It is **not** returned again for 5 seconds. If the ESP32 confirms in that time, the status becomes `acked` (or `failed` for `rejected` or `failed`) and the command is never offered again.
4. If no confirmation arrives (a lost ack, a reboot), the command is offered again after 5 seconds with a higher `attempt`. After 5 attempts it is marked `failed` and dropped. A command that nobody collects within 60 seconds is dropped as `expired`.
5. So the firmware should **remember the ids it has run** (the last 16 are enough). If an id comes again, do **not** run it again: just send the acknowledgement again.

## 7. Firmware flow

```
boot:   locked = true
        token = Preferences.get("token")
        if token is empty:   POST /device/register  { mac, firmware }
                                201 -> save token (device_id is not needed)
                                403 -> wait 10 s, try again   (operator has not opened the pairing window)
                                409 -> stop and show an error  (operator must run "reset")
loop (every 1 s, in its own task so the motor and sensor logic never wait for the network):
        POST /telemetry  (Bearer token)       401 -> delete the token, go back to registering
        GET  /device/commands
              locked = (state.auth == 0)
              for each command in order:
                  if id was run before:  ack "executed" again, skip
                  else: run it, remember the id, ack "executed" (or "rejected" / "failed")
```

## 8. Arduino example (ESP32 core 3.x, ArduinoJson 7)

Not tested on hardware. The only constant is the server address. The token is stored in flash.

```cpp
#include <WiFi.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>
#include <Preferences.h>
#include <time.h>

const char* WIFI_SSID = "YOUR_WIFI";
const char* WIFI_PASS = "YOUR_PASSWORD";
const char* BASE_URL  = "http://192.168.1.19:5173/api/v1";   // laptop address, not a secret
const char* FIRMWARE  = "1.0.0";

Preferences prefs;
String token;                      // from flash, never written in the source
bool locked = true;                // start locked, unlock only when the server says so
uint32_t doneIds[16]; uint8_t doneNext = 0;

bool wasDone(uint32_t id) { for (auto v : doneIds) if (v == id) return true; return false; }
void markDone(uint32_t id) { doneIds[doneNext++ % 16] = id; }

String isoNow() {                                   // 2026-11-14T11:00:00+05:30
  struct tm t; if (!getLocalTime(&t, 2000)) return "1970-01-01T00:00:00+05:30";
  char b[32]; strftime(b, sizeof b, "%Y-%m-%dT%H:%M:%S+05:30", &t); return String(b);
}

int http(const char* method, const String& path, const String& body, String& reply, bool auth = true) {
  HTTPClient h;
  h.begin(String(BASE_URL) + path);
  h.setTimeout(3000);
  h.addHeader("Content-Type", "application/json");
  if (auth) h.addHeader("Authorization", "Bearer " + token);
  int code = String(method) == "GET" ? h.GET() : h.POST(body);
  reply = code > 0 ? h.getString() : "";
  h.end();
  return code;
}

bool registerDevice() {                              // pairing: the MAC address is the only identity sent
  JsonDocument d; d["mac"] = WiFi.macAddress(); d["firmware"] = FIRMWARE;
  String body, reply; serializeJson(d, body);
  int code = http("POST", "/device/register", body, reply, false);
  if (code == 201) {
    JsonDocument r; deserializeJson(r, reply);
    token = r["token"].as<String>();
    prefs.putString("token", token);                 // flash
    Serial.println("Paired as " + r["device_id"].as<String>());
    return true;
  }
  Serial.printf("Register: %d %s\n", code, reply.c_str());   // 403 = ask the operator to open the pairing window
  return false;
}

void ack(uint32_t id, const char* result) {
  JsonDocument d; JsonObject a = d["acks"].add<JsonObject>(); a["id"] = id; a["result"] = result;
  String body, reply; serializeJson(d, body);
  http("POST", "/device/commands/ack", body, reply);
}

void run(const String& type, JsonVariant value) {    // replace the bodies with the real motor and buzzer code
  if (type == "AUTH")       locked = (value.as<int>() == 0);
  else if (type == "STOP")  { /* motor off, buzzer on */ }
  else if (type == "RESET") { /* clear the stop and the alerts */ }
  else if (type == "ACK")   { /* silence the buzzer */ }
  else if (type == "LIMIT") { /* speedLimitKmh = value.as<float>(); */ }
}

void pollCommands() {
  String reply;
  int code = http("GET", "/device/commands?limit=10", "", reply);
  if (code == 401) { prefs.remove("token"); token = ""; return; }      // reset by the operator: pair again
  if (code != 200) return;
  JsonDocument r; if (deserializeJson(r, reply)) return;
  locked = (r["state"]["auth"].as<int>() == 0);
  for (JsonObject c : r["commands"].as<JsonArray>()) {
    uint32_t id = c["id"];
    if (!wasDone(id)) { run(c["type"].as<String>(), c["value"]); markDone(id); }
    ack(id, "executed");                                               // a repeated id is only acknowledged again
  }
}

void sendTelemetry() {
  JsonDocument d;                                                      // device_id is not needed: the token identifies the car
  d["timestamp"] = isoNow();
  JsonObject s = d["sensors"].to<JsonObject>();
  s["alcohol_adc"] = analogRead(34); s["distance_cm"] = 45.6;
  JsonObject a = s["accelerometer"].to<JsonObject>(); a["x"] = 0.12; a["y"] = 0.08; a["z"] = 9.72;
  JsonObject g = s["gyroscope"].to<JsonObject>();     g["x"] = 0.02; g["y"] = 0.01; g["z"] = 0.03;
  s["speed_rpm"] = 85; s["ir_pulse_count"] = 20;
  JsonObject p = s["gps"].to<JsonObject>();
  p["latitude"] = 12.841901; p["longitude"] = 80.224845; p["fix_valid"] = false; p["satellites"] = 0;
  JsonObject al = d["alerts"].to<JsonObject>();
  al["alcohol"] = false; al["overspeed"] = false; al["accident"] = false; al["obstacle"] = false; al["buzzer"] = false;
  String body, reply; serializeJson(d, body);
  int code = http("POST", "/telemetry", body, reply);
  if (code == 401) { prefs.remove("token"); token = ""; }
  else if (code != 201) Serial.printf("Telemetry failed: %d %s\n", code, reply.c_str());
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println("MAC for pairing: " + WiFi.macAddress());
  configTime(19800, 0, "pool.ntp.org");
  prefs.begin("accialert", false);
  token = prefs.getString("token", "");
}

void loop() {
  if (WiFi.status() != WL_CONNECTED) { WiFi.reconnect(); delay(1000); return; }
  if (token.isEmpty()) { if (!registerDevice()) delay(10000); return; }
  sendTelemetry();
  pollCommands();
  delay(1000);       // in the real firmware run this in a separate task; the safety logic must never wait for HTTP
}
```

## 9. What the backend does with a reading, and network setup

1. Checks the token, content type, size and every field.
2. **Stores** the reading in the table `device_telemetry` (device time and server receive time). Readings older than 24 hours are removed.
3. Shows it on the dashboard: live cards, charts, map, alerts and the event log.
4. Switches the dashboard from "Waiting for ESP32" to live data on the first valid reading. There is no simulated data in the system: before the first reading the dashboard shows no values and no position.

Conversions used for the dashboard (the stored values are the raw values sent):

| Dashboard value | Calculated from |
|---|---|
| Speed (km/h) | `speed_rpm × 0.204 m × 60 / 1000`. Change `WHEEL_CIRCUMFERENCE_M` in `config.py` to match the wheel |
| Acceleration (g) | m/s² divided by 9.80665 |
| Tilt (degrees) | angle between the accelerometer vector and the vertical axis |
| Alcohol level | `alcohol_adc × 1023 / 4095` (the dashboard limits are on a 0-1023 scale) |
| Vehicle state | EMERGENCY if `alerts.accident`, WARNING if any other alert is true, otherwise RUNNING |

**Position.** The GPS module is the main reading. When `fix_valid` is `false` (or the module sends 0, 0), the dashboard shows **this laptop's location** instead, taken from the browser of the open dashboard page (the browser asks for location permission once). The badge then reads "Laptop location (±N m)". The laptop location is used for the danger-zone checks only when it is accurate to 200 m or better, and only if it is less than 2 minutes old. With no GPS fix and no laptop location, the position is "No position", nothing is drawn on the map and no zone checks run. The telemetry the dashboard receives carries `position_source` (`GPS`, `LAPTOP` or `NONE`) and `position_accuracy_m`.

Network setup:

1. The laptop and the ESP32 are on the **same Wi-Fi network** (not a guest network that isolates devices).
2. The server listens on all addresses (`0.0.0.0`, port 5173).
3. Find the laptop address with `ipconfig` (IPv4 of the **Wi-Fi adapter**). It can change after a restart, so reserve it in the router or check before each demo. It is the only address the firmware needs.
4. **Windows Firewall.** Windows normally asks "Allow access?" the first time Python starts listening. Allow it for the network type your Wi-Fi uses (check with `Get-NetConnectionProfile`: Public or Private). On the test laptop the Wi-Fi was **Public** and an inbound Allow rule for `python.exe` (Python 3.13) already existed for the Public profile. The rule belongs to that Python program, so start the server with the same Python. If the ESP32 cannot connect while a browser on another device can, add a rule in an administrator terminal: `netsh advfirewall firewall add rule name="AcciAlert 5173" dir=in action=allow protocol=TCP localport=5173 profile=any` (use `profile=private` only if your network is Private).
5. Start the server (`python backend/app.py`) and check `http://<laptop-ip>:5173/api/v1/ping` from a phone on the same Wi-Fi.
6. On Windows, open the dashboard with `http://127.0.0.1:5173/`. The name `localhost` can add about 2 seconds to each request.

## 11. Older shared key (deprecated)

The earlier shared key (`X-API-Key`, from `ACCIALERT_DEVICE_API_KEY` or `backend/data/device_api_key.txt`) still works for **POST telemetry only**, and then `device_id` is required in the body. It cannot collect commands. Turn it off once the ESP32 is paired by starting the server with `ACCIALERT_ALLOW_LEGACY_KEY=0`.

## 12. Known limits

* One token per device and no per-device permissions beyond that.
* A command reaches the ESP32 within one poll interval (about 1 second). There is no push.
* The speed limit of the zone the car is in is still sent as `LIMIT`. The full zone list is sent as `ZONES` (see "The ZONES command").
* Pairing is protected by the operator opening a time-limited window and by the MAC address. On an untrusted network another device could copy a MAC address inside the window, so keep the window short and use `--mac`.
* The rest of the dashboard API (`/api/...`) is still open without login. See the software audit report.
